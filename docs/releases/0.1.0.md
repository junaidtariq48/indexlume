# Indexlume 0.1.0

Indexlume is an open-source, self-hosted search operations platform powered by Typesense.

## Highlights

- Search operations dashboard with projects, sources, collections, Search Studio, indexing jobs, analytics and role-based settings.
- Upload, single-table PostgreSQL and bounded multi-table relational projection ingestion.
- Durable jobs, deterministic documents, staged collection generations, guarded alias promotion and reconciliation.
- Owner, administrator, editor and viewer roles with project isolation and protected public search keys.
- Backup/restore, encryption-key rotation, migration verification, security scans, SBOM generation and acceptance evidence.

## Installation

Follow the pinned requirements and Compose quickstart in the [README](https://github.com/junaidtariq48/indexlume/blob/v0.1.0/README.md). Replace every development placeholder in `.env.example` before using Indexlume outside local development.

## Upgrade and rollback

This is the first public release. The repository contains 12 forward Prisma migrations. Back up PostgreSQL plus the Typesense, Redis and upload-staging volumes—and retain the matching encryption/HMAC/search-pepper secrets—before changing revisions. Application rollback alone is not a database rollback; restore the previous consistent backup set as documented in the [backup and restore guide](https://github.com/junaidtariq48/indexlume/blob/v0.1.0/docs/BACKUP_RESTORE.md).

## Distribution boundary

The attached release assets contain Indexlume source code only. They do not contain an Oryxsol-hosted Typesense or Redis image. Typesense and Redis retain their independent licenses, and operators obtain/build service components as documented in the repository. See the [license review](https://github.com/junaidtariq48/indexlume/blob/v0.1.0/docs/LICENSE_REVIEW.md) and [third-party notices](https://github.com/junaidtariq48/indexlume/blob/v0.1.0/THIRD_PARTY_NOTICES.md).

## Known limitations

- The initial production target is a self-hosted, single-machine Compose deployment.
- Hard deletes require complete reconciliation when a source does not expose a supported soft-delete marker.
- Polling is eventually consistent and is not presented as CDC or cross-system exactly-once delivery.
- Raw query text and top-query analytics are intentionally not stored.
- Published benchmark numbers are observations from documented local hardware, not capacity guarantees.

The attached `release-manifest.json` records the exact source revision and archive digest. Verify the downloaded assets against `SHA256SUMS` before use.
